STEP 2: fresh findings (each one reproduced against the current `dist/` build; `pnpm test` passes 23/23)
1. [LOW] `app/agent/src/sellerCore.ts:330-334`: the tail check doesn't cover `,` and `;`, so filter values are still cut short with no error. `token_symbol: NV,DA` gives `{token_symbol:"NV"}`, `NV;DA` gives `"NV"`, and `token_symbol:NVDA,TSLA` gives `"NVDA"`. This is the same bug class as round-5 #1. Fix: add `,;` to the tail class (`/["'()\[\]{}<>&\\,;]/`), so punctuation directly followed by a symbol character throws. A separator followed by whitespace, as in `NVDA, tool: x`, would still pass. Add these three probes to the gate-5 #1 test.
2. [LOW] `app/agent/src/sellerCore.ts:280`: the tool value is cut at `\b` with no tail check, so a longer or suffixed tool name quietly resolves to an allowlisted tool. `tool: get_spread-v2` gives `get_spread`, `tool: get_oracle_latest.v2` gives `get_oracle_latest`, and `tool: get_oracle_latest"x` gives `get_oracle_latest`. Fix: capture the whole run with `([^\s,;"'()\[\]{}<>&\\]*)` instead of `([a-z_][a-z0-9_]*)\b`. Then reuse the filter tail check and allowlist the full token, so `get_spread-v2` hits `unknown tool`.
3. [LOW] `app/agent/src/sellerCore.ts:280` and `:322`: a single optional backslash only handles one level of escaping. Double-escaped prompts like `{\\\"tool\\\":\\\"get_cross_issuer\\\"}` don't match at all and quietly fall back to the default `get_spread` report, which is the round-5 #2 symptom again. Fix: use `\\*` instead of `\\?` before each quote, for both the key and the value side. Add a double-escaped test case.
4. [LOW] `app/agent/src/sellerCore.ts:280` and `:322`: the anchor `[^A-Za-z0-9_-]` still accepts `.` and `"` as a key start. So `meta.tool: get_oracle_latest` and `x"tool": "get_oracle_latest"` both select `get_oracle_latest`, and the same goes for `meta.underlying`. Fix: exclude those characters from the anchor and move the optional backslash and quote after it: `(?:^|[^A-Za-z0-9_.\\"'-])\\*["']?tool`. That way `{"tool"`, `{\"tool` and `'tool'` still anchor on `{`, space or start, and `x"tool"` and `.tool` don't. Add both probes to the gate-5 #3 test.
5. [LOW] `app/agent/src/sellerCore.ts:331`: the new `&` tail rule rejects query-string-shaped prompts. `tool: get_cross_issuer underlying=NVDA&x=1` now returns 400 `bad underlying`; before round 5 it gave `NVDA`. It fails closed before payment, so nothing is mis-served, but it is a behaviour change with no test. Fix: either treat `&` followed by `key=` as a separator (`/&[A-Za-z_]+=/` → accept the token), or keep the rejection and add a test that pins it as intended.
