NEEDS_FIXES

1. **HIGH** — `app/agent/src/sellerCore.ts:199-236` (`runWork`, which never throws) combined with `app/agent/src/mcpMain.ts:451-472`. In the ERC-8183 `notify_funded` path, whatever `runWork` returns goes straight to `signing.submitResult`. Before this change, a transport failure threw and nothing was submitted, so the funded job stayed open to retry or refund. Now these cases all produce a deliverable that gets signed on chain as the "completed" work for a job the buyer already paid for:
   - an upstream 5xx, a 402, a timeout, ECONNREFUSED, or a caller abort becomes an `upstream_error` or `payment_required` envelope;
   - an upstream reply with `result.isError` becomes a result marked `ok` (see finding 2).

   The x402 paid path does not avoid this either: it settles payment before running the work (`studio-runtime` chunk-NODAFSUU.js:870-890), so "never throw" gains the buyer nothing there. **Fix:** keep the envelope for logs and evidence, but make `runWork` throw (for example `throw new Error("upstream_error: <httpStatus>")`) whenever `status !== "ok"`. That way `notify_funded` never reaches `submitResult` with an error payload. Add a test that asserts it rejects on 402, on a transport error, and on `isError`.

2. **MED** — `app/agent/src/sellerCore.ts:162-164` (`classifyUpstream`). MCP reports tool failures, such as bad arguments or an unknown symbol, as HTTP 200 with `result: { isError: true, content: [...] }`. The code treats any non-undefined `result` as `"ok"`, so a failed tool call is reported as a successful gap report. **Fix:** return `"upstream_error"` when `parsed.result?.isError === true`, and add that case to `sellerCore.test.mjs`.

3. **MED** — `app/agent/src/sellerCore.ts:93-96` and `:231`. The comment says "Only a caller-supplied abort propagates", but the `catch` in `callStockgapTool` swallows every error, including the caller's `AbortSignal`. So an aborted job is recorded as a `transport_error` evidence row and turned into a normal deliverable. The `try/catch` fallback in `runWork` at :202-215 can then only run for programming errors. **Fix:** in the catch, `if (signal?.aborted) throw signal.reason ?? error;` and only map timeouts and network errors to `httpStatus 0`. Tell the two apart with `timeout.aborted`, and record the timeout as a distinct `transport_error: "timeout"`.

4. **MED** — `app/agent/src/sellerCore.ts:233` (`upstream: { url: call.url, ... }`). Every deliverable sent to the buyer includes the upstream StockGap URL. Upstream runs with `MCP_PAY_MODE=free`, so a paying buyer learns a free endpoint that does the same thing and can skip the seller entirely. If `STOCKGAP_MCP_URL` ever carries a token or basic-auth, that leaks too. **Fix:** leave `url` out of the deliverable (keep it only in the evidence sink), or replace it with a constant label such as `"stockgap-mcp"`.

5. **MED** — `Dockerfile:9-24`. The verified image runs as `uid=0(root)` (checked with `docker run ... id`), and the runtime writes the decrypted keystore to disk inside that container. It is also a single-stage image that ships `typescript`, `tsx`, `src/` and `tests/`. **Fix:** add `RUN chown -R node:node /repo/app/agent` and `USER node` before `CMD` (making sure the keystore materialization dir is writable by `node`), and either use a multi-stage build or `pnpm --filter stockgapseller-agent deploy --prod /out` so the runtime stage carries only `dist/`, prod `node_modules` and `studio.toml`.

6. **LOW** — `app/agent/src/sellerCore.ts:182-190` (`parseRequest`). One regex accepts either `token_symbol` or `underlying` and then remaps the value to whatever key the chosen tool uses. `"underlying: NVDA"` with the default tool becomes `get_spread {token_symbol:"NVDA"}`, which is the wrong namespace (tokens look like `NVDAon`). An unknown `tool:` value silently falls back to a different product (`get_spread`) for a paid job. **Fix:** only accept the key that matches the selected tool, and return or throw an `invalid_request` instead of silently falling back.

7. **LOW** — `app/agent/src/sellerCore.ts:113-114`. `res.text()` has no size limit, and the whole body is copied into memory, the evidence file and the deliverable that gets submitted. **Fix:** read the body stream with a cap (for example 1 MiB, the same as the seller's input limit) and classify anything larger as `upstream_error`.

8. **LOW** — `app/agent/src/sellerCore.ts:147-148` (`recordEvidence`). Every tool is written to `get_spread_calls.jsonl`, the file grows without limit, and in free mode any public caller can add raw response bodies to it. **Fix:** name the file after the tool, or use a neutral `upstream_calls.jsonl`, and add size-based rotation or a max-bytes guard.

9. **LOW** — `.dockerignore:5-7`. `.env` is excluded only at the repo root; `**/.env` is missing, so an `app/agent/.env` would be copied by `COPY app/agent`. **Fix:** add `**/.env`. While there, pin the base image by digest (`node:22-bookworm-slim@sha256:...`).
